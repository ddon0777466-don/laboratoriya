# Сеть класса: подключение бесплатного Firebase (5 минут, один раз)

Делает учитель. Ученикам ничего настраивать не нужно.

1. Открой https://console.firebase.google.com и войди в Google-аккаунт.
2. «Создать проект» → любое имя (например, nextlab) → Google Analytics можно отключить.
3. Слева «Сборка» → **Realtime Database** → «Создать базу данных». Регион любой. Режим: **тестовый**.
4. Вкладка **Правила**. Замени содержимое на это и нажми «Опубликовать»:

```json
{
  "rules": {
    "rooms": { ".read": true, ".write": true },
    ".read": false,
    ".write": false
  }
}
```

5. Вкладка **Данные**: сверху скопируй адрес базы, он похож на
   `https://nextlab-12345-default-rtdb.firebaseio.com` (без слэша на конце).
6. Открой файл игры в текстовом редакторе, найди строку
   `const MP_URL = '';` и вставь адрес между кавычками:
   `const MP_URL = 'https://nextlab-12345-default-rtdb.firebaseio.com';`
7. Загрузи файл на GitHub Pages как обычно.

## Как пользоваться
- Кнопка **👥 Класс** → имя и код комнаты (например, 7K2Q) → «Войти». Каждый класс или группа берёт свой код.
- У каждого ученика свой роутер со своим случайным именем сети и паролем. Чужая Wi-Fi сеть видна в списке, но подключиться можно только если друг сам назвал пароль.
- После подключения компьютеры в одной сети видят друг друга: ping, открытие страниц (IIS), IP из DHCP.
- Ученики видят аватары друг друга на карте и могут писать в чат.

## Ограничения бесплатного тарифа
- До 100 одновременных подключений (хватит на ~100 учеников).
- Около 10 ГБ трафика в месяц: ~30 учеников в течение часа ≈ 0,4 ГБ.
- Правила выше открывают только ветку `rooms`; пароли хранятся как хеш, но это учебная игра, а не защита от взлома.
- Для проверки без правки файла можно добавить в адрес `?db=https://...firebaseio.com`.
